# 驗收與證據界線

全部合成；沒有實際 skill、GitLab、多 VM 或真人試用證據。npm test 僅驗 triage baseline。修改後獨立 review／原型驗證由執行者記錄，不預宣稱通過。

## 最小任務走查

用 REVIEW-INTEGRATION.md 的取消訂單／額度只釋放一次案例，走完推薦 → 接手 → 分析就緒 → 人確認 → 模擬發布失敗／恢復 → 作者回應 Q1 → 請求複核 → B 接手局部範圍並確認結果；C 另有未結束輪次。

作者、reviewer、旁觀者只讀共享摘要即可指出：請求誰、誰已承諾、哪版／範圍看過、Q1 是聲明還是已接受、下一步。agent 走查只證明觀察到的操作／語意，真人理解仍待試用。

## 反例

| 案例 | 必須看到／不得誤稱 |
|---|---|
| 分析就緒但未確認；空結論 | 待檢視／無可確認結論；不能發完成 |
| 人確認但發送失敗 | 保留結論、未發布，不稱通知成功 |
| timeout／同輪重跑／跨機競爭 | 先核對 key，未知就停，不盲重送或稱 exactly-once |
| 作者只回 Q1，Q2 未回 | Q1 已回應待檢視、Q2 待回應；不稱全部解決 |
| 無 skill 自然語言 | 可連問題／版本／請求；不明可回原文更正 |
| Label 全空但請求 B 複核 | requested 仍在，接手者無；不消失、不稱 B 已接受 |
| 新 head／head 同但 base 或 target 改 | 明示上下文需確認，不替換舊結論 SHA |
| R2 只看 Q1 | 不稱全 MR 已審或其他 approver 已同意 |
| B 完成 C 未結束；R1 晚到 | 保留 C／R2，不清整個 MR |
| 缺頁／403／404／無來源人工 Label | 未知／待核對，不當零待辦或清除 |
| comment 成功 Label 失敗 | 分開結果，只恢復同步、不重貼 |
| 人工標記衝突 | 不反覆加回或整批覆寫 |
| 無跨 writer 保障 | Label 自動化停用，comment／請求仍可用 |
| 已 approve 等 API | 保留等待與接續者，無新證據不催 merge |
| 已問／個人略過／團隊等待 | 作用不同，各按新證據條件重提 |
| 選入未啟動 | 個人待辦，不是通知／接手；有下一步入口 |
| 手編結論再改其他欄 | 手編保留、不無聲覆寫 |
| 崩潰只留 start | 當時已開始，現在未知 |
| AI 強於證據／私人跨 MR 筆記 | 回到來源與未知，不公開私人工作區、不稱安全可 merge |

## 三種驗證分開

1. 文件／程式檢查：入口、契約、無公司資料與多餘架構；baseline 與新原型測試分列。
2. 合成互動走查：操作、畫面、鍵盤／復原及限制；模擬發布只驗流程，不驗通知。
3. 內部真人試用：依 INTERNAL-VALIDATION.md 驗能力及價值，建立手填／通知／追問基準；Label 十輪記殘留、清理者與次數。

正常流程若仍需固定清 Label、重貼已發訊息或自行拼接證據，不能稱降低協調成本。comment-only 已滿足任務可停止擴張。無基準不自訂 SLA、秒數或提升比例。
